谁发布的

「驾享悦维」（DriveCare AutoCare）由柴琳独立开发。应用关于页写的版本是 V1.0.0，包名是 com.drivecare.autocare。应用界面是中文。

开发者没有为这个应用运营接收车辆数据的服务器。你填写的内容用来在本机计算里程、油耗、花费和提醒。

存在本机的内容

Room 把数据放在应用私有目录的 SQLite 数据库 autocare.db。首次设置必须填写车主姓名、车牌号和当前里程。品牌和车型可以不填。电话、邮箱和 VIN 在「系统设置 → 车主信息」里，可以留空。

存在哪里具体字段
车辆档案一行姓名、电话、邮箱、车牌、VIN、品牌、车型、购买日期、当前里程。保养间隔和保养提醒公里数，保险提醒天数，年检提醒天数（默认 45，设置页没有单独输入框）。货币和单位的默认值是 CNY、km、L、L/100km。三个通知开关。
保养日期、当时里程、下次保养里程、间隔、项目、地点、费用、备注。
加油日期、里程、升数、单价、总价、油品标号、加油站、小票文件路径、备注。
保险类型、公司、保单号、起止日期、保费、到期前提醒天数、保障说明、是否归档。
洗车日期、类型、地点、费用、1 到 5 的评分、小票文件路径、备注。

设置页能改的提醒阈值是：保养间隔、保养提醒公里、保险到期天数、洗车间隔天数。

小票照片

加油和洗车可以用系统的 Photo Picker 选一张图片。应用把它复制成私有目录 receipts 里的一张 JPEG，数据库里只存这个文件的路径。不申请 READ_MEDIA_IMAGES 或 READ_EXTERNAL_STORAGE，也不保留相册里的原始地址。

删除某一条加油或洗车记录时，会删除它对应的小票文件。设置里的「清空全部本地数据」会删掉数据库里的档案和四类记录，不会删除 receipts 目录中的图片。卸载应用会连同这些图片一起删掉。

提醒

打开首页时，「提醒中心」按本机记录算出保养、保险和洗车提醒。这个计算不联网。

另外，WorkManager 大约每 24 小时用同一套规则再算一次，并把结果发成系统通知。这个任务不要求网络。Android 13 及以上只有在已授予通知权限时才发。Android 12 及以下没有这道运行时询问，任务会直接发。手机重启后，RECEIVE_BOOT_COMPLETED 让这个任务还能排上。

保养通知写的是超期或剩余里程。保险过期通知的正文可以同时写出保险公司和保单号。即将到期的保险通知写出保险公司和剩余天数，不写保单号。洗车通知写的是距离上次洗车的天数。这些文字只出现在本机。

「通知方式」里的三个开关都写进车辆档案。首页和每日任务都不读取它们。「邮件提醒（预留）」不会发送电子邮件。

导出、导入、删除

「系统设置 → 数据备份 → 导出 JSON」通过系统的保存对话框写文件，建议名是 autocare_backup_ 加上当时的时间，类型是 JSON。文件里有车辆档案、保养、加油、保险和洗车记录，以及小票在本机上的路径，没有图片本身。应用只负责写入你选中的那个地址，不把文件传到开发者。

「导入备份」读取你选中的 JSON，先删掉现有的数据库记录，再写入文件里的记录。小票图片不会跟着这份 JSON 走。若你在系统选择器里把导出位置选成网盘，那是系统在同步你选的文件夹，不是这个应用在上传。

单条删除在对应的列表里。「清空全部本地数据」会先询问，确认后删除数据库记录，范围见上面的小票说明。

系统备份

应用把 android:allowBackup 设为 false，并在自动备份和设备迁移规则里排除数据库、共享偏好和文件。Android 的自动云备份不会带走 autocare.db 和 receipts。

权限

应用自己的清单声明了两项权限，没有声明 INTERNET，也没有位置、相机、麦克风、通讯录或存储权限。

权限用途
POST_NOTIFICATIONSAndroid 13 及以上用来显示本机保养、保险和洗车通知。拒绝后，应用内提醒中心仍可查看。Android 12 及以下没有这道运行时询问。
RECEIVE_BOOT_COMPLETED重启后重新安排大约每天一次的本地检查。

开源库

界面用 Jetpack Compose 和 Material 3。数据库是 Room。每日任务是 WorkManager，并且把网络要求设为不需要。小票图片用 Coil 从本机文件显示。导入导出用 kotlinx.serialization。图表用 Vico。这些库随应用在本机运行。没有广告 SDK，没有统计 SDK，没有第三方登录。

儿童

本应用不以 13 岁以下儿童为对象。它没有单独的儿童账号。

政策变更

行为或本页说明有变化时，会改上面的生效日期。

English

Effective 21 October 2026. DriveCare AutoCare, package com.drivecare.autocare, version 1.0.0, is developed by Chai Lin. The in-app language is Chinese. The developer does not run a server that receives vehicle records.

What stays on the device

Room stores one SQLite database, autocare.db, in the app's private storage. First launch requires the owner's name, the plate number, and the current mileage. Brand and model are optional. Phone, email, and VIN are edited under Settings → owner info and may be left blank.

The profile row also stores maintenance interval and warning distance, insurance warning days, an inspection warning default of 45 days (no separate field on the settings screen), currency and unit defaults (CNY, km, L, L/100km), and three notification switches.

Maintenance rows store the date, odometer, next-service mileage, interval, job items, place, cost, and note. Fuel rows store the date, odometer, litres, unit price, total, grade, station, receipt path, and note. Insurance rows store the type, company, policy number, start and end, premium, warning days, coverage text, and whether the policy is archived. Car-wash rows store the date, type, place, cost, a rating from 1 to 5, receipt path, and note.

Receipt photos

Fuel and car-wash screens use the system Photo Picker. The app copies the picture into a JPEG under the private receipts directory and stores that path. It does not request READ_MEDIA_IMAGES or READ_EXTERNAL_STORAGE, and it does not keep the gallery URI.

Deleting one fuel or car-wash record deletes its receipt file. Clear all local data deletes the database rows and does not delete pictures already copied into receipts. Uninstalling the app deletes those files with the rest of the private storage.

Reminders

The home screen's reminder list is calculated from local records when you open the app. That calculation does not use the network.

WorkManager runs the same rules about every 24 hours and posts the result as system notifications. The job does not require a network. On Android 13 and later it posts only when notification permission is granted. On Android 12 and earlier there is no runtime prompt, and the job posts directly. RECEIVE_BOOT_COMPLETED lets that work be scheduled again after a reboot.

A maintenance notification states overdue or remaining kilometres. An overdue insurance notification can include both the insurer and the policy number. A not-yet-expired insurance notification includes the insurer and the days left, not the policy number. A car-wash notification states the days since the last wash. The text stays on the device.

The three switches under notification settings are saved on the profile. Neither the home screen nor the daily job reads them. The switch labelled as a reserved email reminder does not send email. The manifest does not declare INTERNET.

Export, import, and deletion

Settings → data backup → export JSON writes a file through the system save dialog. The suggested name starts with autocare_backup_. The JSON contains the profile and the four record lists, including receipt paths, not the image bytes. The app writes only to the location you pick. It does not upload the file to the developer. If you choose a cloud folder, that sync is the system's, not a request from this app.

Import reads a JSON you pick, deletes the current database rows, and writes the rows from the file. Receipt images are not inside the JSON.

System backup and permissions

android:allowBackup is false. Cloud backup and device-transfer rules exclude the database, shared preferences, and files, so Android's automatic backup does not take autocare.db or receipts.

The app manifest declares POST_NOTIFICATIONS and RECEIVE_BOOT_COMPLETED only. It does not declare location, camera, microphone, contacts, or storage. On Android 13 and later, refusing notifications still leaves the in-app reminder list available. Android 12 and earlier have no runtime prompt for that permission.

Libraries, children, contact

The interface is Jetpack Compose and Material 3. Storage is Room. The daily job is WorkManager with network not required. Coil reads receipt files from local storage. Import and export use kotlinx.serialization. Charts use Vico. There is no advertising SDK, analytics SDK, or third-party login.

The app is not directed at children under 13. It has no separate child account.
